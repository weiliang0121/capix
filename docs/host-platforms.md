# 宿主能力与验证范围

Node.js 是 CAPiX 的完整回归基准。在 Node.js 22.23.2 及以上版本，应用通过各包的公开入口接入，模块解析器自动选择 Node 原生实现。其他 JavaScript 宿主按实际使用的能力接入，当前已验证的组合包括 iOS Hermes 模拟器。

## 宿主需要提供什么

| 使用时机                          | 框架会用到什么                                                             | 接入方式                                                                                                                                                                                  |
| --------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 创建结构、资源声明或调用身份      | v4 UUID                                                                    | Node 使用原生生成器。默认条件使用 `globalThis.crypto.randomUUID()`。缺少该方法时，在创建第一个身份前调用 `installRandomUUID(generate)`。模块顶层就可能创建 Offer。                        |
| 构建结构、捕获 View、校验模型输入 | 在读取对象元数据前识别 Proxy 等不适合反射的对象，并判定原生 Error、Promise | Node 自动安装原生判定。其他引擎可在启动时提供 `installObjectInspection(adapter)`。能保证输入来源的宿主也可显式选择 `useAuthorProvidedPlainObjects()`，由作者承担下述责任。                |
| 在子结果接纳期间执行固定实体操作  | 识别父调用当前接纳的直接子调用                                             | 所有宿主都可以把接纳回调第二参 `permit` 交给 `applyFixed`、`intake` 或 `receive`。默认条件要求显式传递。Node 还支持从当前异步接纳作用域读取身份。普通子调用、结果交付和排空可以直接使用。 |
| 通过模型 Provider 发起 HTTP 请求  | 兼容 Fetch 的传输。流式响应需要可读的字节流，取消需传递到请求              | 配置中的 `fetch` 优先，省略时使用 `globalThis.fetch`。应用可按自己使用的协议检查请求、增量正文、最终回复和取消。                                                                          |

采用作者保证时，受检查的对象、嵌套值和会被遍历的原型链都要排除 Proxy 和具有原生回调的宿主对象。应用可以从已知的原始 JSON 文本构造业务数据，把原生句柄保存在资源操作的闭包内。普通数据仍须通过框架的类型、属性和预算检查。子结果凭据绑定本次接纳，回调结束后失效。[对象检查](runtime-boundaries.md#宿主对象检查) · [子结果凭据](runtime-boundaries.md#返回接纳与实体落实)

包解析器需要支持 ESM `exports` 和包内 `imports`，并按宿主选择 `node` 或 `default`。`platform-node` 是 `platform` 的安装依赖，默认入口不会加载其 Node 内建模块。启动配置和框架消费者应解析到同一份平台模块实例。[包职责与依赖](organization.md#执行与外围装配)

## 验证范围

| 环境                                                | 已验证的范围                                                                                                                                                                            |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node.js 22.23.2                                     | `pnpm check` 执行全仓构建、类型、包内与仓库测试、平台检查、示例及文档验证。另有仓外安装检查覆盖发布包。                                                                                 |
| iPhone 17、iOS 27.2 模拟器，标准 Hermes Release App | 显式配置对象策略后通过 29/29 个公开能力场景。12 个包的 484 项既有回归中，使用可读的 HTTP 流时通过 482 项。另外 2 项验证 Node 的隐式异步接纳作用域。模拟器验证了用显式凭据完成固定写入。 |
| 浏览器条件                                          | Runner 与模型 Provider 可以使用通用入口打包，产物无 Node 内建模块。浏览器中的端到端运行、网络流和持久存储仍需分别验收。                                                                 |

移动端的 CP 用例将内存 Store 导入新实例并在同一进程恢复。设备持久存储、进程被系统终止后的恢复，以及特定厂商的线上服务，需要用相应宿主和服务单独验证。[框架测试说明](testing-organization-design.md) · [平台实验与用例](../scripts/platform/README.md) · [iOS Hermes 接入](ios-hermes.md)
