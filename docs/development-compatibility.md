# 开发期兼容与仓库边界

状态：2026-11-07，用户明确旧存量无需迁移。本约定替代早期设计中的旧格式升级、只读兼容和长期保留旧解码器计划。

## 当前格式

| 层                    | 当前支持                                      | 遇到旧格式                                              |
| --------------------- | --------------------------------------------- | ------------------------------------------------------- |
| Checkpoint            | Frame v6，完整逻辑镜像与增量 Commit           | 拒绝旧 Frame，不升级、不提供 v5 只读支路                |
| Conversation 数据库   | SQLite schema 8                               | 只新建空库或打开当前库；旧库在修改前拒绝                |
| Observer 内容数据库   | SQLite schema 6 与当前 CP 表结构              | 旧 schema／旧 CP 表拒绝，不转换内容或退休历史数据来适配 |
| Conversation 模型交互 | `conversation.completion.v2` 完整原生回复契约 | 不提供旧文本 v1 的 `readHistory` 或合成续接材料         |
| 业务恢复声明          | 当前准确 key/version、成员位置及恢复资格      | 不迁移声明，不忽略版本差异                              |

拒绝不等于自动删除。宿主可选择新数据库路径，确需重置时由用户明确处置原文件。普通启动不能改写旧库，也不能在恢复失败后自动创建“同一个”空对话。

当前格式仍支持重启载入内容、按交互身份读取反馈、恢复当前 CP、完整镜像冷导入，以及针对介质损坏和未知提交结果的拒绝规则。删除旧版本适配不改变这些能力，也不省略当前值域、容量、归属、修订和终态检查。

## 保留和性能

“不迁移旧存量”与“当前运行不保留依据”是不同决定。当前 head、准确事实、已使用身份和选择墓碑仍按恢复及拒重契约保留；没有新增自动整树退休、长期硬配额或跨实体事务。

CP 热保存处理新增事实、变化关系和选择增删；完整 state 编码、作者主动全量检查与冷恢复全量核验仍按实际工作付费。当前实现与测量见 [Checkpoint](checkpoints.md) 和 [增量选择](checkpoint-selection.md)。未来若提出长期容量治理，应先确定恢复依据的保留与释放权限。

## 外部业务装配

外部业务项目可以只读参考 CAPiX，并通过公开包装配资源、结构与宿主。业务项目内的一次任务不授权修改 CAPiX，也不授权把业务凭证、绝对环境路径、治理要求或部署规则写入 CAPiX。

发现框架缺口时，在业务项目保留最小复现和建议，回到 CAPiX 的独立任务由用户决定是否修改内核。仓库内参考服务用于检验公开内核，但其业务选择不自动变成全框架不变量。具体规则见 [AGENTS.md](../AGENTS.md)。
