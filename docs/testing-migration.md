## 实际变化

20 个包各有 `test/` 与 test 脚本。原根测试按断言拆分，类型正负例、JSON 依据和进程 worker 跟随所属包；原 241 个文件已逐项核对后移除旧路径。只有 3 份失去执行入口的旧合成场景数据删除；正式用例没有因迁移删除或跳过。

根目录只保留 `testing/support` 的纯异步工具与 `testing/repository` 的工作区、依赖、发现和分发检查。Runtime 保留真实装配组合的夹具，公共工具不包装 Scene/Runner。测试之间不跨包导入私有夹具。

- View 用最小 ViewSource 假体测试自己的契约，真实 Transcript/Memory 来源适配各归实体包。
- 客户端状态机与 HTTP 编解码拆分，client-runtime 不为测试反向依赖 client-http。
- 结构声明和作者类型归 structure；依赖 Runner 的预设执行、CP 与输出组合归 runtime。
- Frame/MemoryStore 认证归 checkpoint；单次调用与热依据归 invocation；结构化绑定和恢复归 runtime。
- 资源本身的活动与操作测试归 resources，Runtime 建立供给、捕获与失效的测试归 runtime。

根 workspace 开发依赖从 20 个框架包收敛到示例实际需要的 11 个；Runtime、Resources、Interaction 的测试依赖在本包显式声明。生产依赖、源码和 exports 未改变；Node/TypeScript 等工具仍集中管理。

## 独立验证与新增回归

CAPiX 的 test、check、CI 和分发验收不加载 capix-lab，不需要本地服务、数据库或模型密钥。Lab 只读参考以下混合证据后，在框架重新表达最小回归：

- checkpoint 的增量 Store、选择认证和关系缓存：只保留 MemoryStore 与端口契约。SQLite 事务、物理行和宿主恢复资格仍由具体实现验证。
- 协议记录和客户端 handled 接纳：不拉入参考服务或 UI。
- Runtime 的增量选择跨进程恢复：保存后真实退出，在另一进程向新 MemoryStore 按原 revision 重放公开提交，核对原 selection/occurrence 身份、精确删除、单项追加、兼容跨点零增量以及效果不重放。测试文件只传输提交材料，不声称提供生产文件存储或 SQLite 原子性。

测试执行器拒绝空测试范围、缺 test 脚本、未知包与缺少构建出口；类型目录中的 .test.mjs 编译入口正常发现，fixture 不当作独立测试。边界检查同时解析静态导入、动态导入和 TypeScript import 类型，拒绝跨包私有路径、未声明框架依赖及测试依赖环。

CI 顺序执行 `check` → `release:check` → `integration:check`。前者不重复构建；后两者分别验证 17 个压缩公开发布物和 20 个普通候选包。两个消费者都在仓库外临时安装 tarball，验证全部公开出口与运行/类型使用。候选验证有独立摘要回执，不把它当成压缩产物证明。两类打包共用白名单，拒绝误编入 dist 的测试、fixture 和 benchmark。
