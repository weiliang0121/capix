# 统一操作模型：全仓迁移

状态：2026-10-25 用户确认目标，先保存迁移文档和现有代码基线，再实施。本文优先于历史文档中的配置替换、独立正常接纳和独立异常处理声明。范围是整个仓库，不是只重写 Callable 文件。

## 目标

结构持有配置，run 组织业务操作，Invocation 执行统一机制。Scene / Group 组织直接成员，Node 负责直接处理；资源是声明和注册好的受控操作。业务作者主要理解操作的 delta / result，以及 work.checkpoint / work.observation。

Callable 保留身份、kind、可选解释信息、deps、run、output、checkpoint。构造时可以提供配置，也允许 build 前按字段完成局部组装。删除 setRun、setDefinition、configure、replaceRun、replaceDefinition 及其整份替换/清空语义，不引入同义新门面。build 检查完整性并原子固定整树，失败允许修正重建，成功后不再修改。资源端点和本次状态不保存在结构。

删除普通声明上的 accept、exceptions、raises、maxRounds 和独立异常资源类型。普通业务没有 receive / handling 两套作者阶段，不以字段改名或 hidden legacy definition 保留原执行路径。正常 run 中申请本层 deps，使用已登记子成员；不再为普通 run 重复登记 uses。恢复点保留自身明确的依赖与行动范围。

## 操作与交付

```ts
const value = await work.children.translate.invoke(text, {
  delta: (part) => work.output.emit(part),
  result: {
    succeeded: checkTranslation,
    failed: (failure) => translateWithAlternative(work, text, failure),
  },
});
return value;
```

资源操作使用相同 delta / result 形状。成功回调接收真实值；失败回调只接收允许由业务处理的操作失败。没有回调则成功值直达，失败向外传播。回调自身失败不再次进入同一 failed 回调。父层处理失败不改写子调用的失败返回；接纳转换后的值与原返回分别保存。操作的已知来源必须随真实交付保留，不能按最近一次错误或错误对象扫描猜测。

业务循环、有限再尝试和备用路径属于 run；不能为了旧 round / continue 测试把一个两轮异常解释器留在新调用路径中。取消、装配、必要事实提交和严格观测失败仍受内核约束，不被业务 fallback 清除。资源失效、关闭窗口、已启动子调用和接纳排空、独立 Interaction 生命周期均保持。

output 是生产者最终结果与增量的契约；消费端的 result / delta 是本次操作的接收行为。成功结果保持引用。最终结果与预览、丢弃和失败分别表达，不能把多次候选的 delta 拼成一个伪造结果。调用和资源观测由机制发布，业务自定义事实通过 work.observation；记录消费者由宿主装配，不要求每个节点安装 observation 声明。服务原有正文描述、敏感正文排除、任务角色仍须有明确的记录侧归属。

## CP 与恢复的例外边界

暂时保留具名点、codec、Frame、直接子引用、固定效果凭据、恢复资源窗口与持久化检查。需要为恢复编码的具名接纳契约归于 CP 配置，不再使普通节点承担一套额外接纳阶段。

保留机制不代表所有历史业务 CP 自动兼容。迁移改变某条业务路径或状态含义时，升对应声明版本并明确拒绝不兼容的旧 image；不自动重发外部交互，不从当前文件猜历史效果。旧轮次/异常诊断读取若仍需要，限制在 CP/历史记录解释边界，不能向新普通 Work 暴露独立异常阶段。

完整回归覆盖等待子调用、返回未接纳、已接纳、接纳回调失败、失败已处理、效果已落实而 CP 未保存、恢复后继续推进。迁移中如需改变 Frame 格式，应明确版本边界，不能靠类型断言让新旧格式混用。

## 全仓责任与步骤

1. 保存本文与当前代码基线。已有绿测只说明旧行为稳定，不构成保留旧 API 的要求。
2. Runtime 作者面：结构、配置类型、工厂、组合辅助和 Work 同步删除旧入口。保持 I/O/Delta/资源/成员关联，不用 any 或类型断言掩盖作者面错误；异构机制存储的既有擦除边界单独核验。
3. Runtime 机制：Binder、快照、Builder、Invocation 和操作接收采用同一模型。正常调用只执行一次 run 并交付；父接纳、控制、输出和观测是机制职责，不另立业务阶段。精确 CP 句柄仍可用于等待与恢复。
4. Observer：所有 Scene/Group/Node、装配、模型、文件、材料和记忆流程使用新配置和操作；生成失败后的一次再生成改为业务流程，保留真实拒绝依据、调用次数和恢复凭据。记录配置移入记录装配，环境/资源/处理职责保持分离。
5. Client/protocol：核对真实运行事实和投影，不为删旧名字改写持久历史。新活动不能生成已经删除的阶段；历史记录按原事实只读解释。对话、队列、传输与 preview/answer 交接继续有效。
6. 测试/示例/文档/公开出口：删去只证明旧替换或旧异常声明存在的用例，把其中真实不变量改成新模型回归。编译失败用例明确拒绝旧 API，示例能直接运行，根出口不留同义旧类型。

每个阶段先通过相关编译与行为验证，再整仓干净构建、类型检查、测试和格式检查。全仓搜索旧词只能作为定位，不能机械删除 CP、历史 wire、领域名中恰好同名的内容。

## 验收清单

- Callable 没有旧 setter、双重配置解释器、独立接纳/异常声明。
- 构造器与普通赋值表达同一份配置；build 原子固定，结构身份和单次调用身份不混用。
- 资源、子操作统一 succeeded / failed / delta；业务接收错误不递归 fallback。
- 普通 Work 不暴露旧异常处理状态机；可选 CP 的恢复边界明确且可验证。
- 记录和观测不要求业务结构持有消费者；角色、正文投影与来源完整性保持。
- Observer 完整正常、失败、取消、再生成、流式、文件、记忆、恢复链路通过。
- 客户端、协议和历史读取保持事实语义；新旧不兼容的 CP 明确拒绝。
- 类型正例/反例、运行回归、示例和文档都使用目标模型。测试数量不是完成度指标，不能通过批量跳过旧测试回避其真实不变量。

## 非目标

不建立配置热更新/重新绑定生命周期；不推进动态注册、调度平台或新包体系；不使用真实模型验证，不读取环境密钥，不推送、部署或自动重启服务。
