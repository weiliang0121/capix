# Action、局部草稿与资源承诺边界：第十轮验证

2026-11-07。承接[真实调用生命周期与事实表示](invocation-lifecycle-facts-validation.md)。本轮只新增隔离实验与报告，不修改生产 Context／Relation、资源、Frame、恢复资格或现行原引用契约，不提交代码。

## 1. 本轮的边界与结论

用户明确了两项约束：**不承诺草稿恢复；内核不默认承担资源自己的承诺。** Action 指已有的调用、接纳或资源操作，不新增 Action 实体、平行状态机、通用资源能力等级、事务协调器或自动重试。

本轮结果支持把工作分成三部分：

1. 内核负责准确身份、活动窗口、调用与接纳进度、正式交付及自身的持久依据；正式内容的稳定所有权仍是候选，生产尚未迁移。
2. 私有草稿只承担活动中的加工。达到正式边界时形成稳定材料，不跟踪或保存编辑过程。
3. 资源自行提供普通读写、条件更新、准确确认或事务等具体能力；业务的恢复入口按所选契约使用。能力可以组合，但不由 CP 自动产生。

**计算问题不能归结为资源太动态。现有 CP 的主要重复成本在处理内核自己的材料；增加这些计算，并不能增加外部资源的承诺。** 无资源的纯调用实验同样出现历史关系的重复编码和检查。

本轮还发现一个需要单独决定的调用语义：现有实现允许“接纳活动进入后取消，接纳仍成立，父调用最终取消失败”。上一轮提出的“安装接纳前复核取消”尚不是生产规则，不能当作已具备的保证。

## 2. 并发与局部草稿

使用真实 Invocation／Relation／MemoryCheckpointStore，夹具显式用已有 `StableValues` 固定输入、子交付与接纳值。两个孩子返回同一稳定正文，两个接纳回调分别持有私有草稿，经确定性 Promise 闸门交错推进。

```text
两份成功子交付
    ↓
A receiving：编辑 draft A ──→ 固定 A1 ──→ accepted
B receiving：编辑 draft B ─────────────────────→ 固定 B1 ──→ accepted
    ↑ CP：两者 receiving       ↑ CP：A accepted，B receiving
```

实测：

- 开启／关闭 CP 得到相同正式内容；CP 开启时可以保存混合的 accepted／receiving 截面。
- B 尚在加工时，Relation 没有 B 的接纳 output；CP 不取得半成品。
- B 草稿额外修改 1,000 次，调用 Frame 不变。草稿带函数与检测枚举的 Proxy，CP 对其枚举次数为 0。
- A 正式交付后修改 A 的原草稿，已固定 A1 不变。
- 两个孩子即使交付同一对象、正文相同，仍保留不同 contextId、order 和两份接纳事实。

这是**活动私有材料不进入正式保存选择**的实验，不是通用防逃逸系统：夹具明确没有把草稿传给 CP、存入结构或泄漏给其他活动。生产原引用仍允许别名影响内容；本轮没有自动安装固定机制，也没有给任意外部对象套 Proxy。

共享目标的并发则由资源决定：真实资源窗口中两个局部字段更新可以后发先完成并同时成功；真实 Memories 对同一依据的两个提案，第一次成功后第二次以 `MEMORY_BASIS_CONFLICT` 拒绝。过期依据上的空提案也拒绝。内核没有统一规定“所有资源必须拒绝第二次写入”或“自动更新依据后重试”。

## 3. 事务和零内容变更

使用真实 ResourceBinding／ResourceAccess、Memories／MemoryResource 和 Invocation：

| 情形                            | 结果                                                    | 保证的所有者                     |
| ------------------------------- | ------------------------------------------------------- | -------------------------------- |
| 普通字典资源，无版本／凭据／CP  | 正常运行，关闭后端点失效                                | 资源窗口；字典 origin 无额外协议 |
| Memory 批次带无效目标           | 提交前整批拒绝，0 次提交                                | Memory 的批次校验                |
| Memory 成功，随后第二个资源失败 | Invocation 失败，Memory 的内容和提交保留                | 两个操作分别成立                 |
| Memory 固定提交后，变化发布失败 | Invocation 失败，内容和凭据保留，可按实体契约确认原操作 | Memory；确认不改变失败调用终态   |
| 普通无变化操作运行两次          | 两次操作正常交付，不要求凭据                            | 普通资源方法                     |
| Memory 普通无变化更新           | 0 新提交、0 内容事件、0 固定凭据                        | Memory 的无变化规则              |
| Memory 固定无变化更新           | sequence／正文不变；新增一次仅凭据的提交                | Memory 的固定操作规则            |
| 重复确认同一固定无变化操作      | 不再提交，不再发布内容变化                              | Memory 的准确确认                |
| 普通 Memory 相同 create 两次    | 两个身份、两次提交，不隐式去重                          | 普通 create 的语义               |

因此必须分别判断：**正文是否变化、资源是否成立新操作依据、当前调用是否推进。** `dirty=false` 不能通用决定是否需要执行资源方法、建立接纳或保存调用进度。反过来也不要求无变化资源一定新增 receipt 或提升内容版本。

Memory 的同步持久端口在这些测试中是内存提交记录器；公共 export／restore 验证实体重建后可按原凭据确认，不能将其单独当作磁盘崩溃证明。下一节另做真实双库硬退出验证。

## 4. 相同调用恢复，资源能力决定效果边界

父层按真实接纳契约进入 receiving，保存正式请求材料后访问资源。资源 SQLite 与实验 CP FactStore 使用**独立文件、独立事务**，通过公开 ResourceOffer／ResourceAccess 端点执行。

切点固定为：

```text
子成功交付已保存
→ 父 receiving CP 已保存
→ 资源效果已提交
→ process.exit(73)
   （资源方法尚未返回，接纳尚未完成，finally 没有执行）
```

新进程复用第九轮的真实 `prepareCheckpointRestoration`／Invocation 恢复路径。仍核验原父子身份和接纳契约；成功子正文不重跑。

| 恢复路径                      | 效果数：退出前 → 恢复后 | 行为                                             |
| ----------------------------- | ----------------------- | ------------------------------------------------ |
| 普通 append，作者原样重入回调 | 1 → 2                   | 负对照：调用恢复不会赋予资源幂等性               |
| 作者明确拒绝无依据续接        | 1 → 1                   | 不再次访问资源；进入恢复后父层失败，覆盖范围缩小 |
| 资源持有准确操作凭据          | 1 → 1                   | 资源方法进入两次，第二次确认原效果；父层完成接纳 |
| 同一操作身份换请求            | 1 → 1                   | 资源拒绝，原效果保留                             |
| 原凭据缺失                    | 1 → 1                   | 资源拒绝，不推断“效果没有发生”                   |

五种情况的子正文均只执行一次。已终结父调用仍拒绝再次恢复，资源的准确确认不会复活内核终态。

草稿含进程局部标记，测试确认未写入 CP；恢复建立新草稿，消费已保存的正式请求。没有保存编辑进度、Promise 或闭包。普通路径也不要求资源识别操作 key；只有明确选用确认能力的路径才把相应依据交给资源。

这里的资源是独立 SQLite 实验实现，不是任意外部 API。准确确认在该资源内把请求、效果和凭据事务保存；该能力并非来自内核。试验覆盖的是效果已提交后的切点，缺凭据路径选择拒绝，没有借此宣称所有“提交前／后未知”情况都可续接。

一个边界解释是：如果“外部已写入”和“外部未写入”给内核留下同样的最后 CP，内核重复编码、哈希或扫描这些材料，仍无法区分两者。需要额外证据时，必须来自声明了这种能力的资源或宿主。

## 5. 现行计算成本：已经固定的值仍被重复处理

`action-cost-study.mjs` 使用实际 Invocation／Frame v5／MemoryCheckpointStore，显式固定交付值；不使用 LifecycleAdapter 的额外成立时 codec，不改变生产捕获逻辑。父输入为 1 KiB，每个孩子有小输入、小返回值、独立接纳；父在派发前及接纳后各保存一次，refs 为空，作者 check 不扫描历史。

只统计**父 save 内**的编码、解码及接纳检查，不包含孩子自己的 save／finish、父 finish、正常接纳时的首次 check。本轮为确定性调用次数实验，不提供耗时、吞吐、堆内存或物理写入收益结论。

| 指标                                            |  N=32 |  N=128 |   N=512 |
| ----------------------------------------------- | ----: | -----: | ------: |
| 外部资源访问                                    |     0 |      0 |       0 |
| 父保存次数 `2N`                                 |    64 |    256 |   1,024 |
| 累计捕获子关系 `N(N+1)`                         | 1,056 | 16,512 | 262,656 |
| 子返回 encode 次数 `N²`                         | 1,024 | 16,384 | 262,144 |
| 接纳 encode 次数 `N²`                           | 1,024 | 16,384 | 262,144 |
| 保存中 reception.check 次数 `N²`                | 1,024 | 16,384 | 262,144 |
| 上述返回 encode 中处理前步骤内容的次数 `N(N−1)` |   992 | 16,256 | 261,632 |
| 父 input encode 次数 `4N`                       |   128 |    512 |   2,048 |
| 显式固定器在整次运行的访问数 `8N+4`             |   260 |  1,028 |   4,100 |

各 encode 对应 decode 次数相同。最后一次 accepted 保存仍编码／检查 N 个返回和接纳、编码 2N 次子输入；不是只处理当前新增关系。

固定器计数只表示夹具的 `StableValues` 遍历次数。保存期间它的访问增量为 0，**不代表 CP 没有遍历正文**：生产 clone／JSON／codec 仍执行。正式数据已经固定，也不会自动改变现有 Frame 的工作范围。

N=128 的两个独立对照：

- 每个接纳草稿增加 1,000 次修改，共 128,000 次：父保存数、CP 回调数、逻辑镜像字节和固定器访问数与无编辑对照完全一致。局部赋值本身当然仍有 CPU 成本；没有为每次赋值创建版本或快照。
- 将局部计算换成 128 次真实普通资源端点读取，保持相同输入输出：CP 计数不变。关闭 CP 后，128 次资源访问与稳定交付仍发生，父 save 内计数为 0；正常接纳的首次 check 并未被取消。

这些结果说明，当前大量成本不负责外部一致性，也不是草稿变化多导致的，而是**保存入口仍重新捕获和验证全部旧调用材料**。

## 6. 合适承诺与计算范围的对应

| 工作                     | 应保证的范围                                       | 本轮支持的处理方向                                                      |
| ------------------------ | -------------------------------------------------- | ----------------------------------------------------------------------- |
| 正式数据固定             | 当前交付材料不受原草稿别名影响                     | 未知材料形成时隔离一次；可信稳定材料按准确证据复用，不能信任任意 freeze |
| Context／Relation 进度   | 真实身份、顺序、返回／接纳各自成立                 | 只由原所有者安装；局部草稿不成为另一套调用状态                          |
| 活动资格                 | 本次允许进行的操作、取消与窗口规则                 | 本地复核；不扫描全部资源或外部世界                                      |
| CP 热保存                | 新材料、变化的调用关系、本次 point/state/refs 组合 | 不应反复加工已固定旧正文；仍需真实关系完整性与当前组合核验              |
| CP 提交与回执            | 准确 owner、revision、提交不确定、终态不可推进     | 保留，不能因为资源能力强而省掉                                          |
| 冷恢复                   | 持久数据合法、结构兼容、关系与选择正确             | 完整读取校验；不沿用上一进程的信任                                      |
| 资源冲突／事务／效果确认 | 该资源明确承诺的语义                               | 只在选用路径支付对应查询、比较与持久成本；不统一强制                    |
| 作者 check、state、refs  | 当前业务选择的真实依据                             | 成本按实际访问范围计，不能缓存任意闭包检查或禁止合法大材料              |

目标仍应是：热路径工作随新增正式材料、变化的活动关系和显式检查范围增长。不能据此宣称整条链路 O(1)：大 state、全量 refs、作者全量检查、实体构造全量快照、首次编码和冷恢复各自仍可能线性于其材料。

源码定位：[父保存](../server/invocation/src/checkpoint/invocation.ts)、[子关系捕获](../server/invocation/src/checkpoint/children.ts)、[解码与接纳校验](../server/invocation/src/checkpoint/facts.ts)、[refs 匹配和镜像认证](../server/checkpoint/src/value.ts)。此前[完整计算基准](checkpoint-computation-results.md)已测量这些范围的耗时；本轮没有重跑长耗时基准，不将旧数据当作新实现提速。

## 7. 必须单独定性的接纳安装时机

真实低层 Invocation 和公开 Runner 两条测试均得到：

```text
进入异步接纳回调（receiving）
→ 等待期间取消
→ 回调正常返回
→ Relation accepted 成立
→ 父执行收尾检测取消，父调用失败
```

当前 Relation 在回调进入前核验活动，回调完成后检查接纳值并安装；Runtime 作者端同样没有安装前的后置检查。资源操作的接收窗口核验又有自己的位置。参见 [Relation](../server/invocation/src/invocation/relation.ts)、[作者接线](../server/runtime/src/binding/children/binding.ts)、[资源操作](../server/resources/src/activity.ts)。

因此要区分两种承诺：

- 已进入的接纳可以完成，父调用仍可能取消失败：现状事实。
- 取消后禁止安装新的 accepted／handled：更强的候选，需要在真正安装边界规定检查。

夹具在回调末尾手工 `requireActive()`，可以阻止该异步时间线的接纳。但另一个反例中，随后的同步 `reception.check` 取消调用，现状仍安装 accepted。这证明把 guard 交给业务回调并不能替代内核安装边界的规则。

本轮不选择或修改这个生命周期规则。它属于内核自己能控制的边界，应结合退出契约明确；不应该要求外部资源更强来掩盖，也不能因资源效果可能已发生而推导哪种接纳规则必须成立。任何选择都不回滚此前已落实的资源效果。
