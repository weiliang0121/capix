## 1. 本轮要证明什么

上一轮证明稳定交付可以与真实调用的故障边界协作，但生产保存仍重新捕获、编码全部历史。本轮沿三条线验证：

1. 稳定值摘要按节点计量，避免兄弟污染，同时保持固定工作与持久展开预算分离。
2. 稳定输入/返回/接纳事实首次发布，后续 head 只保存关系日志位置及本次 state；测量正文、元数据、引用和作者检查分别增长多少。
3. 实体相同版本的快照可复用，但检验跨版本全量构造和 View 来源版本的边界。

结论：**在独立模型内，正常后续保存可以不访问、不编码旧事实正文，也不扫描全部旧关系。** 这依靠首次发布的事实、增量关系/引用登记、持久派生索引及固定字段数、不含历史目录的 head 元数据共同成立。只移动正文、不改变 refs 的累积写法，仍然会平方增长。

这不是任意 CP 的 O(1) 保证：新正文、本次 state、作者实际检查、索引查询、SQLite 成本仍存在；冷恢复仍全量核验。也没有证明完整生产恢复契约已经迁移。

## 2. 固定值：修正及明确的语义变化

`StableValues` 在每个新节点完成后保存高度、展开内容摘要和实验编码字节摘要。父节点沿每条边累加；同一源对象只固定一次，旧可信子节点只读摘要。整次成功后才发布证明。

| 项         | 本轮规则                                                        |
| ---------- | --------------------------------------------------------------- |
| 固定工作   | 计新检查对象、边与文本；跨次可信子图不重新扫描                  |
| 展开内容   | 每条边都累加子内容，不能因 DAG 去重而少算                       |
| 格式字节   | 绑定当前实例上限和 `stable-value-study@1`；不证明任意业务 codec |
| 超限摘要   | 饱和到上限加一，只表示超限，不宣称精确大数                      |
| 固定与编码 | 小共享图可以固定成功，树展开编码仍可拒绝                        |

100 层共享 DAG：固定访问 102 个值（101 对象和一个字符串），摘要处理 201 条边、908 文本单位；编码拒绝只读根证明一次，没有展开。500 条新边引用同一个 4,000 字符旧正文：只新处理一个对象、500 条边，旧文本处理为零；展开文本超限仍拒绝。

原有三项“组合时按整次证明收费并在 own 拒绝”的测试已按新规则修订，另加四项测试。**这是实验预算契约的修正，不是保持原接纳集合的透明优化。** 一次性 own 和分批 own 的实际工作预算可以不同；同内容的编码接纳不依赖这种分批。O(1) 只指可信对象摘要读取/预检，实际编码仍随输出字节增长。详情见 [算法说明](../examples/checkpoint-facts-study/algorithm.md)。

## 3. 事实、关系和 head 的分工

```text
调用输入 / 孩子返回 / 父接纳
              │  成立时固定内容，尚不执行持久 codec
              ▼
        本次拥有的稳定事实
              │  首次需要保存：编码、往返核验
              ▼
     facts：不可变正文 + owner/kind/codec/digest
              ▲
              │  fact/link 发布准确事实身份
关系推进 ──→ events：按 owner 追加的事实、关系、ref 变化
              │
              ├──→ relations / refs / publications：派生查询索引
              ▼
     head：input 引用、point/state、终态、cursor/chain、子数量
```

这些都是实验内部角色，不新增用户必须注册的 Fact 实体或通用日志系统。

- `facts` 正文写一次。该 writer 后续保存不再执行旧事实 codec；不是每次重新编码再比较，也不是按任意 `(object, codec)` 猜测纯性。
- `events` 保存准确关系推进与引用更新。head 指向本 owner 已提交的完整事件前缀，没有复制所有 fact ID 或 refs 数组。
- 派生索引按变化更新。热路径点查旧元数据，不在每次保存重建整张 Map。
- `publications` 区分“数据库有此事实”与“该 owner 的已提交前缀可以引用它”；只知道全局 ID 不获得引用资格。
- 新事实、事件、派生索引、head 修订在同一个 SQLite 事务内发布。事务之外没有第二本在途预留账本，不包含业务实体或外部效果事务。
- 事实成立后、首次保存前，codec 仍可能失败；失败不改写稳定交付或旧 head。已发布表示成为依据，后续不重新调用该事实的 codec。
- 冷恢复从 head 的准确 cursor 折叠整个事件前缀，重新核对哈希、身份、进展、事实正文、codec、引用和派生索引。超 cursor 的行不提前纳入。

**新的检查契约仍是候选。** 本模型新事实首次发布执行 encode/decode 等值检查；每次 point check 仍调用，但只通过只读查询访问事实。它没有实现生产 reception.check，也不证明生产所有 codec 往返保真。停止在每次保存重复检查旧表示，改变的是检查时机，需在正式迁移时明文决定。

### 孩子没有自己的 CP

子交付的语义所有者与持久发布者分开。孩子没有 head 时，父首次保存可以发布其 input/returned/failure 以及父 accepted/handled；不会隐式创建孩子 head。孩子已有成功交付时，恢复路径可直接 link 准确的持久事实，不重新编码该输出。

本模型没有生产声明层，不能把此测试称为“未声明 CP / 声明但未 save 两类装配集成验证”。它验证两类共有的存储条件；实际实现的 `finalize` 仍以首份 CP 为门槛。额外覆盖：构造模型 child writer 不 save，finish 拒绝，父仍可保存已成立返回。

同一已发布事实在本 writer 内不重复编码；**不承诺跨 writer 的所有输入核对零编码**。例如父已经发布孩子输入，孩子建立自己的第一份 CP 时仍编码原输入以核对相同表示，随后 link 同一正文行。

### waiting 与已接纳结果

- waiting：固定准确子身份、输入、契约；恢复查孩子后来形成的持久 head。缺 head 拒绝，不新建调用或重发效果。
- 子有合法活动 CP：交付 continuation 的点与 state，由明确续接处理消费；不重跑原正文。
- 子已成功：引用准确交付，再执行父层尚未保存的接纳。
- 父已保存 accepted/handled：读取自身固定事实，不追随孩子最新 head。
- 子失败尚未 handled：不能保存成可续接 active head。失败与 handled 分开；不把替代结果伪造为孩子成功。

## 4. 审查发现与修复

| 发现                                      | 修复与反例                                                                        |
| ----------------------------------------- | --------------------------------------------------------------------------------- |
| receipt 只有事件位置，未绑定 state/status | 独立计算并核对完整 headDigest；篡改 owner/revision/cursor/chain/headDigest 均拒绝 |
| 冷恢复 relation 是可变 JSON 对象          | 恢复交给调用前重新固定关系/ref/事实；修改 phase 或 identity 抛错且历史不变        |
| check 可重入 save 或改调用                | 只读 facade 加保存期排他；闭包重入/创建/finish 拒绝                               |
| 引用全局已有、但未在 owner 前缀发布的事实 | 每 owner 发布资格索引；事务拒绝且回滚，不写出自身无法恢复的 head                  |
| 派生关系表物理 key/order 未核对正文       | 冷恢复核对 SQL child/position、正文身份与折叠前缀                                 |
| continuation 被父 codec 重解码            | 使用已由孩子 head.stateCodec 解码的 state；不同子 state codec 只解码一次          |

Store 进入后发生异常或回执无效，当前 writer 标记 uncertain，拒绝继续 save/finish，不把“回执失败”解释为“没有提交”。编码阶段失败发生在进入 Store 之前，旧 head 保持可用。已提交的失败或成功终态均不能复活。

## 5. 跨进程切点

使用独立临时 SQLite（WAL/FULL）与 `process.exit(73)`，绕过 finally。另一个库只统计真实 fixture 效果/映射次数，恢复逻辑不读取该计数作依据。

| 硬退出位置                                                 | 新进程行为                                  | 效果次数 / 映射次数 |
| ---------------------------------------------------------- | ------------------------------------------- | ------------------- |
| 父 waiting 的 facts/events/before-head/head，提交前，共4点 | 回到 prepared、尚未派发；实验不自动创建孩子 | 0 / 0               |
| 父 waiting 已提交、孩子未建立                              | 缺首子 CP，拒绝                             | 0 / 0               |
| 效果已发生、孩子首 CP 未建立                               | 拒绝，不能以重跑补齐                        | 1 / 0               |
| 孩子 finish 提交前                                         | 从其 completed-body 点续接                  | 1 / 1               |
| 孩子 finish 提交后                                         | 读已成立子交付                              | 1 / 1               |
| 父接纳 facts/events/head 提交前，共3点                     | 子效果不重跑，未保存的纯映射重算            | 1 / 2               |
| 父接纳已提交                                               | 固定接纳值直接读取                          | 1 / 1               |
| 子成功但回执丢失、父失败提交前                             | 持久父仍 waiting，读孩子成功                | 1 / 1               |
| 同上，父失败已提交                                         | 终态拒绝复活                                | 1 / 0               |
| 根 finish 提交前                                           | 从已保存接纳继续完成                        | 1 / 1               |
| 根 finish 已提交                                           | 终态拒绝复活                                | 1 / 1               |

16 个切点通过；每个成功恢复案例再启动一个进程，验证再次恢复不重复效果或映射。同步 rollback、修订冲突、缺失/损坏正文、事件缺口、错误 owner/codec、错误索引、错误引用、保护失败和未处理失败另外由单元反例覆盖。

这是**新协议模型**的数据库恢复验证。既有 `receipt-recovery` 是真实 Runner/Invocation 的对照，并未换用本实验格式；两者通过不能相加成“生产新格式已经保留全部恢复资格”。

## 6. 规模与负对照

基准：固定父输入 50 KiB、孩子输出 64 B，N=32/128/512/2048；每个孩子等待前和成功接纳后各保存一次，再保存一次无变化 head。每项三次独立进程/新库，冷恢复在另一个全新进程执行。额外 N=128 的 500 KiB 输入、16 KiB 输出，以及全量作者 check / 重复提交旧 refs 两个负对照。

最终产物：`.capix/fact-head-study-20261106-final/summary.json`。24 次执行、24 个独立冷恢复进程；产物保存四个实验源码的 SHA-256，各次一致并与测量时当前文件匹配。较早的 `-incremental` 目录只保留探索记录，不用于下表。

下表耗时取三个独立运行的中位数；末段为最后约 10% 保存的 p50，再取三次中位数。保存累计不含最后一个无变化探针。

| 子调用数 N | 等待/接纳保存数 |  保存累计 | 末段单次保存 p50 | 全量冷恢复 | 最终 head 字节 |
| ---------: | --------------: | --------: | ---------------: | ---------: | -------------: |
|         32 |              64 |  16.35 ms |         0.203 ms |    6.38 ms |            459 |
|        128 |             256 |  51.18 ms |         0.155 ms |   15.67 ms |            463 |
|        512 |           1,024 | 174.39 ms |         0.147 ms |   46.51 ms |            464 |
|      2,048 |           4,096 | 637.04 ms |         0.136 ms |  138.63 ms |            467 |

小样本受启动/JIT和系统噪声影响，p50 下降不代表历史越长越快。更可靠的是路径计数：普通 waiting/accepted 分别写 3/5 条元数据事件、执行 7/16 次元数据查询；首次 waiting 另发布父输入（4事件/9查询）。这些数量不随旧孩子数量增长。最终 head 的少数字节变化来自十进制计数长度，不含旧关系目录。

N=2048 共首次编码并持久化 6,145 个事实、写 16,385 条事件。保存过程旧数据库正文读取为零，普通作者 check 下 save 内事实值查询为零；每个已发布事实没有再次调用 codec。完整恢复读取全部 6,145 份事实并折叠 16,385 个事件，不沿用进程内证明。

无变化探针：新增事实 0、事件 0、旧正文读取/事实值查询 0；仍执行一次作者 check、一次 state 编码、head/input 元数据核对与 head 更新。它不是没有工作的保存。

其他配置，均 N=128：

| 配置                   | 保存累计中位数 | 观察                                                                                                 |
| ---------------------- | -------------: | ---------------------------------------------------------------------------------------------------- |
| 基线 H=50 KiB / V=64 B |       51.18 ms | 1,025 事件                                                                                           |
| H=500 KiB              |       53.40 ms | 固定输入首次编码一次，不随每次保存重新付费                                                           |
| V=16 KiB               |       84.99 ms | 每个新增输出/接纳仍付正文成本；不是消除所有大值工作                                                  |
| 作者全量 check         |       51.80 ms | 实际扫描 16,512 条关系、查询事实值 32,768 次；这里只取值引用，没有深遍历正文，不能凭耗时接近就称免费 |
| 每次重提交全部 refs    |      172.81 ms | 事件从 1,025 增到 17,537；末段 p50 从 0.155 增到 0.935 ms，旧正文仍零重读                            |

最后两个负对照证实：稳定正文与增量表示不能替作者消除历史遍历，refs 的公开表达若仍要求每次重交全量数组，会把平方增长重新带回来。

计时范围 `saveMs` 包含完整 FactCall.save（作者 check、state、首次事实编码、事务）；`preparationMs` 单列创建、稳定返回/接纳及 refs 登记，避免把准备成本挪出图表就宣称消失。逻辑字节不等于 SQLite 页/WAL 写量；数据库最终文件大小另存。没有生产 Brotli、资源窗口、真实 Invocation 退出或完整 Frame v5 认证，不能拿该毫秒数直接与生产基准相除宣称提速。

## 7. 实体快照对照

使用真实公开 Transcript、Memory、View，增加本目录实验缓存 wrapper，没有修改实体包。

- Memory 同一不可变快照重复读取只固定一次；更新后旧值保留。实体原来的冻结对象不会自动取得稳定值认证。
- Transcript 缓存绑定实体与准确 `[0,end)`。追加不改变旧前缀；最多保留两个版本，淘汰后重建。缓存版本数有界不意味着正文空间固定。
- View 缓存按成员与来源的复合 basis。记忆正文更新不改变 View 成员 revision，但必须失效重读。命中时正文读取和固定访问为零，公开来源目录核验仍执行；来源不可用/范围错误不能借缓存绕过。

每步追加一条固定大小消息、读取完整前缀两次：

|   N | 源前缀条目累计 | 固定访问累计 | 缓存命中 | 保留引用槽位 |
| --: | -------------: | -----------: | -------: | -----------: |
|  32 |            528 |        1,616 |       32 |           63 |
|  64 |          2,080 |        6,304 |       64 |          127 |
| 128 |          8,256 |       24,896 |      128 |          255 |

缓存省掉同版本第二次读取，但每版本首次完整数组构造仍平方增长。View 的全量成员更新也没有被这个读取缓存解决。若要继续降低跨版本成本，需要前缀共享/分块或范围读取等独立设计，不能从本实验直接推出。

## 8. 已证明和未证明

| 本轮成立                                                  | 仍不能宣称                                             |
| --------------------------------------------------------- | ------------------------------------------------------ |
| 同 writer 已发布事实在后续普通 save 中零重编码/零正文访问 | 任意 codec/check 自动纯化，或任意作者 save 总成本 O(1) |
| 增量事件、索引和位置 head 避免热路径完整关系扫描          | 保留完整 refs 数组的现有作者 API 可无代价获得相同收益  |
| no-head 子结果由父发布；waiting 读后续孩子进展            | 已迁移生产全部 CP 声明、结构兼容与宿主资格             |
| SQLite 同事务发布与跨进程切点可行                         | 业务效果、实体写入和 CP 构成共同事务                   |
| 新进程完整重检持久数据                                    | 热路径每次都重新检测旧正文损坏                         |
| 活动 head 不含全部历史 ID                                 | 总内存、累计存储或活动关系数量天然有界                 |

特别的信任边界：热路径假设此 Store 的已提交事实/索引不被其他写者绕过修改；旧正文只在首次发布和冷恢复时验证。哈希链检测对应材料的缺失/损坏，不是抵御能整体改写数据库者的安全签名。运行中物理损坏的发现时机与生产每次全量校验可能不同，需要正式契约明确。

原型保留全部事实和事件，没有 GC/退休/压缩；FactCall 仍持有本调用全部稳定事实与关系，内存 O(累计事实)，不是有界活动缓存。索引 B-tree 查询仍有数据规模相关成本，不能把点查数量固定理解为 CPU 严格常数。

表示的限制包括：没有全部 v5 kind/round/progress 字段；没有当前声明注册表兼容解算；只有命名的单值 refs 增量登记，没有 typed many/删除/完整点槽位规则；失败可接收性由夹具给定，不是实际 Invocation 故障归属；state 使用实验 codec；未实现生产 reception.check。每条数据仍受实验稳定值预算，但没有把生产 8 MiB 整 Frame 限额原样搬成跨行总配额。以上都是迁移时必须解决的真实契约，不能删测试绕过。

下一步可以进入**统一格式与作者检查/refs 契约的设计**，优先把此模型与完整 Invocation 事实字段、恢复资格对应起来；在这之前不全仓迁移稳定值与只读类型，也不将上一轮 92 项兼容失败当作可以直接删除的旧断言。
