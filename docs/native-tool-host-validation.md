## 交付与边界

CLI/Web 支持启动参数 `--answer-mode tools`，默认仍为 `material`。历史工具为 `search_history`、`read_message`，只访问当前正式用户消息之前的固定前缀。工具模式展示实际阶段与正式回答，不把工具调用前的候选正文拼成答案。直接模型资源仍用于记忆维护；选择工具回答不隐式改动维护策略。

两种模式的普通提交和实际 resume 共用入口门槛；只读查询不门控。每次 run/resume/完整资格核验拥有独立 `ToolExchangeUse` 并在 finally 关闭。独立模型发送及反馈保存不依赖这个句柄存活。

工具根契约为 `conversation.tools.scene@1`；工具完成 CP 为 `conversation.tools.completion@3`，completed 同时保留原 reference 与 reply。恢复核对原请求、完整持久反馈、关系和固定落实凭据；缺少依据拒绝而不重发。工具恢复列表仅给出 unchecked 候选，选中再做完整核验。Frame v5 与材料恢复语义未改。

| 单次回答 | 1 / 0                     | 268 B      | 0.71 MiB     | 0.69 MiB   | 42 / 16       | 79.0 KiB     | 88 ms    |

工具模型次数不含后续的一次记忆维护请求。密集循环是前 7 次回复各要求 32 个工具，最后一次返回正文，模型与工具合计 232 个直属关系。

密集样本的分解：

- 交换集合 363,404 B；Interaction 存量 3,643,881 B；CP 存量 399,717,665 B。
- CP 保存端口同步耗时合计 5.26 s，单次最大 28.70 ms。该计时不包含调用侧此前捕获/编码，不能将余下耗时全部归因于模型或持久化。
- ToolAnswer 新增的 prepared / waiting 镜像分别 509,655 B / 764,991 B，端口同步保存分别 1.90 ms / 6.84 ms。
- 关闭前 SQLite 主文件 12,918,784 B，WAL 4,437,272 B。压缩使物理文件显著小于逻辑存量；该文件大小也不代表进程堆占用。

**主要成本是保留的完整 CP 镜像。** 引用化消除了累计请求正文逐层放大的部分，未消除每次保存完整直接关系及旧镜像全部保留的成本。本样本当前 CP 累计写入量恰好等于保留存量（每个 image/delivery 都保留）；Interaction 不满足这一等式，其状态会被更新。

最初候选 64 MiB 增长缓冲小于密集样本实际增长。本轮默认改为 **2 GiB 入口参考上限、512 MiB 固定增长缓冲、每个在途交互 2 MiB 回复估计**。这是经验门槛，不是证明上界或预留账本；更长历史、更大工具结果仍可超过样本。各单项硬限制继续生效；达到入口门槛后停止新写入入口，没有自动退休。

原始离线报告位于 `.capix/tool-host-offline-20261106b/`，保留当时 64 MiB 配置，未改写历史测量。脚本可用当前默认值重跑，不要求真实模型。

## 结论与保留问题

本次样本验证了原生工具协议在真实宿主中的执行、错误回填、思考续接和退出生命周期，未发现需要新增调用内核机制的阻塞点。内核侧只补充结构身份到既有观测事实投影，阶段展示不修改调用推进。

模型回答仍有质量问题：有时在预算比较后添加不必要的解释，或将历史助手摘要也称为原文。这些是模型/提示与材料策略的评估点，不能由工具执行成功推导出语义准确率，更不应伪装成协议问题。

后续应单独处理 CP 镜像增长与归档退休。候选正文流式、MCP、默认写工具、任意崩溃恢复仍未在本轮交付。接口联通不等于这些范围已经完成。

## CP 当前镜像保留复测（2026-11-06）

本节是 SQLite v6 保留策略实施后的独立复测，上面的历史结果保持原样。每个调用保留当前 head 的完整镜像和已有交付；被替代的镜像只保留身份、所属调用及修订，正文置空。没有删除已完成子调用或根 head，没有修改 Frame v5、业务 CP 点和交互记录。

运行入口：

```sh
node examples/tool-host-study/run.mjs --out .capix/tool-host-cp-retention-20261106
```

三个离线样本全部完成，退出后载入集合数均为零，模型请求/完整持久反馈数分别为 2/2、5/5、9/9（含一次记忆维护）。未调用真实模型。测量保持原来的同步 save/finish payload 累计探针，另在关闭宿主后只读统计保留正文和身份行。

| 样本     | save / finish | 身份行 / 保留正文 / head | 淘汰正文 | CP 存量（原 → 本次） | 累计 CP 写入 | 本次联合逻辑存量 |
| -------- | ------------- | ------------------------ | -------- | -------------------- | ------------ | ---------------- |
| 单次回答 | 42 / 16       | 42 / 16 / 16             | 26       | 0.69 → 0.32 MiB      | 0.69 MiB     | 0.34 MiB         |
| 中等循环 | 90 / 31       | 90 / 31 / 31             | 59       | 7.49 → 2.03 MiB      | 7.49 MiB     | 2.28 MiB         |
| 密集循环 | 742 / 247     | 742 / 247 / 247          | 495      | 381.20 → 14.37 MiB   | 381.20 MiB   | 18.19 MiB        |

密集样本 CP 保留逻辑字节从 399,717,665 B 降到 15,065,652 B，下降 96.23%；交换集合 363,404 B、Interaction 3,643,881 B 保持不变。247 个调用 head 全部保留，742 个镜像身份继续用于全局去重，只有 495 份被替代的正文被淘汰。这里的 CP 存量包含 head 交付；身份行及 SQLite 索引不是 JSON 字节门槛的计量项。

**累计写入仍是 399,717,665 B，742 次 save、247 次 finish 与最大镜像 2,799,139 B 均未减少。** 本次端口同步耗时合计 5.55 s，单次最大 30.23 ms；整次调用耗时 20.71 s，进程 CPU 21.32 s。历史单样本分别为端口 5.26 s、整次 19.59 s，未记录可直接对照的进程 CPU。小/中样本本次调用耗时为 92/356 ms，CPU 为 110/399 ms。一次测量不足以给出速度结论，本次只证明保留存量下降，不声称捕获、编码、压缩或 CPU 成本已下降。

关闭前密集样本 SQLite 主文件 6,463,488 B、WAL 4,540,272 B；物理文件大小受页复用、压缩和 checkpoint 时机影响，不能与 JSON 存量等同，也不承诺已有数据库迁移后立即缩小文件。

诊断 `analyze-frames.mjs` 的报告版本升为 2，区分 `imageIdentities`、`retainedBodies`、`discardedBodies`；字段重复度只分析保留下来的正文，不能据此重建已经淘汰的镜像或累计计算成本。仍可读取格式 v3/v4/v5 的历史实验库；v6 当前 head 正文缺失会明确拒绝。原始复测报告保存在 `.capix/tool-host-cp-retention-20261106/`，不覆写先前容量或真实模型报告。

### 旧实验库迁移与重开

```sh
node examples/tool-host-study/retention.mjs \
  --source .capix/tool-host-offline-20261106b/eight-models-32-slots.sqlite \
  --out .capix/tool-host-retention-migration-20261106 --repeats 3
```

每次复制同一个已关闭的 v5 实验库，用独立进程分别测量迁移与 v6 重开。源文件只经文件系统检查与复制，SQLite 仅打开副本；末尾核对原库 SHA-256 未变。计时不含模块 import、复制及摘要核验；没有清理 OS 文件缓存，也不执行任何模型请求、调用或恢复。

| 次数 | 迁移及关闭 | 迁移 CPU | v6 重开及关闭 | 迁移进程最大 RSS |
| ---- | ---------: | -------: | ------------: | ---------------: |
| 1    |    3.587 s |  3.730 s |       2.89 ms |        254.2 MiB |
| 2    |    3.505 s |  3.655 s |       2.82 ms |        249.0 MiB |
| 3    |    3.465 s |  3.619 s |       2.97 ms |        250.5 MiB |

742 个镜像身份及修订、247 个当前 head 的正文和 delivery、其余内容/Interaction/交换表的摘要都保持一致；正文数量降为 247。逻辑存量与新库复测相同，迁移只在第一次打开时发生。最大 RSS 含模块加载；不是迁移函数独占内存，也不是任意规模库的上限。

主文件由 12,988,416 B 变为 13,250,560 B：迁移重建表留下可复用页，没有执行 VACUUM。这个实际结果也说明逻辑正文减少不等于物理文件立即变小。源库只有一个密集工具入口，不能把约 3.5 秒外推成长期数据库的固定迁移时间；更大历史会增加一次性核验工作。
