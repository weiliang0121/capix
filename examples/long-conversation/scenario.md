# 54 次交错主题对话：人工场景与评阅依据

本场景是人工编写的虚构对话，版本 1，标识 `interwoven-fictional-life`。人物、作品、地点和服务信息均由输入给定，日期统一为虚构的 2040 年，不依赖现实营业信息或联网查询。这里只提供用户输入和人工评阅依据，不包含真实模型回答，也不声称模型已经通过这些检查。

每一轮是一条用户输入，等待本轮正式回答后再提交下一轮。可以在第 24、36 或 54 轮停下，对完整前缀进行评阅；这些位置是实验检查点，与内核 Checkpoint 或执行恢复无关。运行办法和产物说明见 [README](README.md)。

## 数据边界

- [scenario.mjs](scenario.mjs) 导出 `scenario = { id, version, checkpoints, turns }`。每项包含 `id`、`topic`、`tags`、`input`、`expectations` 与 `memoryUpdates`。
- 只有 `input` 作为用户输入交给回答模型。`expectations` 是人工评阅条目，每项含 `claim` 与 `sourceTurns`；不拼入回答、选择或提取模型的请求。
- `memoryUpdates` 仅供离线替身模拟记忆提案。每项含 `key`、`topic`、`content`、`sourceTurns`；它是人工事先写好的理想化主题摘要，不是从模型生成、观察或评测得到的记忆。真实模型运行不得消费这些提案。
- 六个记忆 `key` 与主题一一对应：`project`、`travel`、`reading`、`learning`、`family`、`preferences`。同 key 的后续 `content` 替换该主题的当前摘要；取消用明确状态表达，不模拟删除记忆实体。跨主题核对不建立额外主题。
- `sourceTurns` 使用从 1 开始的用户轮次，不是原文消息索引。所有来源都不晚于当前轮；在每轮恰好一条 user 和一条 assistant、无种子消息时，第 n 轮 user 对应原文索引 `2 * (n - 1)`。
- 多轮 `memoryUpdates` 为空；提问、复述请求、引文命令、临时格式或未被采纳的假设不自动变成新事实。离线替身完成流程只能验证装配与观测，不能证明真实模型的理解或记忆质量。

## 评阅方法

以下完整保留 54 条用户输入，并在三个检查点附上人工核对条目。单轮详细条目均在 `scenario.mjs` 中。评阅时结合该轮实际提供给模型的材料与可追溯的正式消息，逐条记录“支持”“矛盾”或“未覆盖/证据不足”，附实际回答片段。允许等义表达，不按关键词命中就判正确。

若回答材料缺失，回答明确不知道或请求澄清可以避免捏造，但不能记为成功回忆该事实；应分别记录材料是否到达和回答是否忠于材料。若材料含前后冲突，使用已给出的最新纠正，不把旧值与新值折中。实际模型建议不是用户承诺：未获用户确认的建议不能在后续轮次当作已决定、已预订或已完成。

## 边界与未覆盖事项

该场景用固定人工用户输入控制事实来源，没有模拟现实资料检索、工具副作用、真实预订、权限、安全系统、并发提交或执行恢复。它测试的是有限材料下的多主题衔接与事实边界；54 次对话及三个前缀样本不足以建立通用模型能力结论。人工摘要提案也不是生产记忆策略，不能据此声称自动提取、自动召回或语义去重已经可靠。
