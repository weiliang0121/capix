本轮新增 20 项验证（15 项值契约、5 项真实调用探针），连同前两轮共 **41/41 通过**。实验目录格式检查与 `git diff --check` 通过；没有运行全仓测试或重新构建工作区。


真实机制探针使用已构建工作区包；实验自行固定输入/返回/接纳值，内核尚未自动插入这些动作。没有外部模型、生产数据库、服务重启或网络访问。

## 1. 这轮要决定什么

建议采用的语义候选是：**调用的正式输入、成功返回和父层接纳值采用稳定内容；业务加工产生新值，不能改写已成立事实。** 内容固定与成功宣称分开，持久化是第三件事。

这不是“每次调用都 JSON 序列化一次”的建议，也不是要求每个作者调用 `own()`。实验显式调用它，是为了验证边界；若迁移到生产，应由准确的调用入口、交付和接纳边界负责。

| 规则                           | 可观察含义                                                             | 证据                                             |
| ------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------ |
| 输入在首次相关消费前固定       | 捕获、范围解算、正文读取同一内容，调用者保留的原别名不能改变它         | 第二轮真实 Runner 对照；本轮三层 Invocation 输入 |
| 生产者和消费者均不能改写正式值 | 修改原对象不影响副本；修改正式值的嵌套字段、数组、属性也不能成功       | 新的别名、消费者、兄弟读者测试                   |
| 业务转换显式发生               | Date→epoch、trim、包装文本发生在形成正式值之前，恢复不再重做           | 普通与非幂等转换对照                             |
| 固定不代表成功                 | 取消、关闭、必要保存或接纳检查仍可失败                                 | 真实 Invocation 故障用例                         |
| 接纳值与子返回分开             | 父层可交付新值；接纳失败不修改孩子的 returned                          | 三层接纳与修改失败测试                           |
| CP 开关不改变数据形态          | 关闭保存时仍固定内容，不需要执行持久编码；开启保存可以增加真实持久故障 | 真实调用开关对照与编码计数草图                   |
| 内容共享不等于身份共享         | 相同稳定正文可复用，调用和关系身份仍独立                               | 三个真实 Context、两条真实关系                   |
| 新消费契约仍要检查             | 复用跳过的是旧正文复制，不是新消费条件                                 | 相同值通过第一个要求、拒绝第二个要求             |
| 恢复保持值义而非 JS 对象身份   | 字段、值、字段存在性相同；不承诺与旧对象 `===` 或保留共享引用拓扑      | 新进程值恢复、共享引用反例                       |
| 成本必须按表示粒度计           | 小的共享对象图可能展开为很大的值树，固定不能被称作无条件便宜           | DAG 反例与访问次数计数                           |

规则中的“不能改写”指内容保持不变。在 ESM 严格模式下写入会抛 TypeError；非严格代码也可能静默写入失败，不能把“任何误写必然抛错”作为契约。

## 2. 三层的小场景

`stable-runtime.test.mjs` 使用真实 `Invocation`、关系接纳和 `MemoryCheckpointStore`：

```text
调用者原输入
  → 实验显式固定 I1
  → Scene → Group → Node（各有独立调用身份）
                     ↓
               Node 固定返回 O1
                     ↓
               Group 接纳产生 A1
                     ↓
               CP1 → 修改原别名/尝试修改正式值 → CP2
                     ↓
               Group 返回 A1 → Scene 接纳并返回 A1
```

验证：

- 输入 I1 可复用到三层，作者修改原输入后仍为原内容。
- O1 与 A1 不同，父层转换没有改写孩子。
- 修改 producer/mapper 的原别名不会改变已保存内容；消费者尝试改写正式值失败。
- Group→Scene 转交可信 A1 不重新遍历正文，三次调用身份仍不同。
- 开启/关闭 CP 得到相同的数据含义。开启时真实保存两份父镜像并完成交付。
- 孩子没有首份 CP 仍可成功返回；测试不假设每份子事实都已有自己的持久 head。

这条路径证明主动提供稳定数据与当前调用机制相容。它不证明所有公开入口已覆盖，也不证明内核无需调整就能自动执行此策略。

## 3. 失败不会因为内容固定而消失

实际机制覆盖：

- Work.close 失败：孩子候选内容保持不变，父关系收到 failed，而非 succeeded。
- 固定候选后等待期间取消：同样不交付成功，不因候选已经准备好绕过取消。
- 父接纳回调尝试修改孩子固定值：returned 仍成功且原值不变，reception 失败，不产生 accepted output。
- 必要 CP.finish 失败：候选和此前的保存仍按事实存在，但父关系不能宣称成功，不重跑业务。

finish 故障通过公开 MemoryCheckpointStore 包装注入，分别发生在实际提交前、提交成功但回执返回前。后一种情况下，存储中的成功终态仍保留，但父层交付失败；两种情况均仅执行一次正文、一次 save、一次 finish，不二次写入伪造失败。这区分了正文成功、持久事实、父层交付，未模拟真实 SQLite/磁盘故障，也不扩展现有恢复资格。

原 Error 在真实传播中仍保留自身身份；实验另行固定诊断内容，不用纯数据替换 catch/instanceof 所依赖的对象。CP 故障仍允许按现行机制包装，不能要求所有故障原样抛出。

独立同步草图还验证：接纳计算先产生效果，随后遇到不支持的数据或检查失败，之前的效果不回滚。第二轮已有真实接纳边界反例。本轮不新增事务或自动失败补偿。

## 4. 本实验的数据范围

`stable.mjs` 的 `StableValues` 是受限的实验工具，不是新包或待直接复制到内核的实现。

| 形态                                               | 本轮选择                                                    |
| -------------------------------------------------- | ----------------------------------------------------------- |
| null、boolean、string、有限 number                 | 保留；包括 `-0` 的区别                                      |
| undefined                                          | 保留，支持合法无返回值、显式存在的 undefined 字段及数组元素 |
| 普通记录与稠密数组                                 | 复制自有可枚举字符串数据属性并递归固定                      |
| 已由同一工具持有的固定值                           | 允许直接复用；关闭复用后重新复制，含义相同                  |
| 外部冻结对象/另一工具实例的值                      | 不假定可信，重新校验与隔离                                  |
| Date、Map、类、函数、Error、二进制、BigInt、Symbol | 拒绝；作者可显式转换为已支持的数据                          |
| getter、toJSON 方法、非枚举字段、稀疏数组、环      | 明确拒绝，不静默执行/丢弃/规范化                            |
| Proxy 与被恶意修改的全局原型                       | 不提供隔离沙箱保证                                          |

特别发现：**JSON 可保存并不足以证明值义不变。**

```js
const value = { present: undefined, values: [undefined, -0] };
JSON.parse(JSON.stringify(value));
// { values: [null, 0] }
```

因此本轮用了仅供实验的带标签表示，分别保留 undefined/null、缺失/存在字段、-0/+0。字段名 `__proto__` 或形似类型标签的业务内容仍只是普通数据，不改变对象原型或伪造标签。解码也拒绝对象参数，避免 JSON.parse 隐式调用其 toString。

这不是决定生产必须使用此格式。未来可以选择不同支持域与表示，但不能让普通路径和恢复路径悄悄不同；不能把 Date→string 后的类型继续声称为 Date。

### 对象身份不是值的一部分

```js
const shared = stable.own({ text: 'x' });
const value = stable.own({ left: shared, right: shared });
value.left === value.right; // 本地优化可能为 true。

const restored = other.decode(stable.encode(value));
restored.left === restored.right; // 本实验恢复为 false。
```

两边内容等价。需要业务身份时使用明确字段，不依赖共享指针。不能一边要求多层零复制，一边默认恢复必须重建全部 JS 别名拓扑。

## 5. 固定后的计算能省什么

本轮计数结果：

- 可信值连续转交两次：新增旧正文访问 **0**；禁用复用后 **8**，数据含义相同。
- 每个新消费条件照常检查：同一值经过两份契约，检查 **2** 次，第二份可以拒绝。
- 独立新增事实提交草图：第一次编码 I1/O1/A1；第二次只编码 O2；关闭保存时编码 **0** 次。

最后一条中，实验由调用方显式传入新增事实。它只说明稳定值允许复用表示；没有证明生产内核已经会增量捕获、没有重复扫描、能原子提交或提供有界 head。

### 新暴露的成本边界：共享 DAG

第三轮用 9 个对象构造每层 left/right 指向同一前层的 DAG：当时实现缺少单次源对象记忆表，复制展开后访问 767 个值，编码为 18,441 字节。**首次固定的指数展开是该实现的问题，不是稳定值必须承担的成本。** 第四轮已通过单次 memo 将固定访问降为 10；值树持久编码的展开仍需要独立预算。

因此生产候选需要补上**允许的数据图形状与预算**：至少区分唯一对象数、展开内容大小、深度与实际编码字节；不能只按顶层节点数或原对象个数计费。选择有界展开、保留结构共享或拒绝超限，需要独立的小决策；本轮不增加通用图编码。

第三轮没有实现深度/字节/条目限额。第四轮已补实验预算和线性固定验证；这些预算仍不是生产配置或任意外部数据的安全沙箱。

## 6. 恢复验证的准确范围

`stable-restore.mjs` 在新进程重新解码、检查、固定值，并尝试修改其嵌套对象。回传的表示与原材料相同，验证不沿用旧进程 WeakSet 证据。

显式业务规范化只发生在形成正式值前；解码不会重新调用它。另有非幂等文本包装反例，证明重复执行转换会改变含义；正常和恢复的只读检查仍分别执行。

这里恢复的是**值**，不是 Invocation、父子树、恢复点、资源权限或实体事务。既有恢复切点矩阵仍需在真正迁移后执行。正常路径输入/输出的类型如何改成只读、已有 codec 是否保持语义、跨包实体如何获得可信复用，都未由这组 JavaScript 测试证明。

## 7. 可收敛与待迁移的边界

本轮支持把“稳定交付值”作为正式迁移的语义候选：

1. 内容在边界固定；逻辑加工产生新值。
2. 固定、成功成立、持久保存分开。
3. 新消费契约与恢复信任边界照常校验。
4. 原引用身份与共享拓扑不属于数据承诺。
5. CP 只保存已确定内容，不负责在每次保存时重新定义过去交付了什么。

进入生产之前仍需明确：支持值域和预算；输入/返回/接纳的准确插入位置及错误归属；只读类型与现有作者迁移；codec 正常/恢复一致性。固定值证明可以先采用安全的重新隔离路径，不必先建立跨包认证平台。

本轮不修改 Frame、不引入事实平台、全局序号或 GC，也不把“事实固定”当作已解决 refs/state/完整关系检查的历史扫描成本。
