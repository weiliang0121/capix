# 历史工具预设

`createToolConversationParts(content, outputBudget?, policy?)` 组合普通准备节点、工具回答、维护节点及可恢复根 Scene。宿主仍拥有 Transcript、View、模型通道和一次运行的 `ToolExchangeUse`，`parts.register(...)` 只登记接线。

工具模式的初始材料包含本次正式问题和活跃记忆，不直接装入历史消息正文。历史来源固定为当前问题之前的 Transcript 前缀：消息即使退出 View，仍可被显式工具读取；当前问题及后续追加消息不能通过这两个工具读取。这是本服务的材料策略，不是 View 或 Transcript 的通用规则。

| 工具             | 输入                                | 输出与分页                                                                                                                               |
| ---------------- | ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `search_history` | `query`、可选 `fromIndex` / `limit` | 按真实消息索引顺序做区分大小写的字面搜索；每条消息返回首个匹配及有界片段。`nextIndex` 是下一条尚未搜索的消息。没有匹配也可能仍有下一页。 |
| `read_message`   | `index`、可选 `offset` / `length`   | 返回原消息的有界片段，保留角色、绝对索引、总长度和 `nextOffset`。偏移与长度使用 JavaScript UTF-16 位置，不拆开有效代理对。               |

默认每次搜索最多扫描 256 条消息、返回 6 个匹配、每段最多 120 个 UTF-16 单位；读取片段最多 1024 个单位。搜索不是语义召回，也未建立全文索引：成本仍包括实际扫描的消息长度。读取与搜索会继续缩短正文，以同时满足工具原始输出上限和反馈 JSON 编码上限；真实索引、偏移和下一页位置不会被截断或重编号。

两个工具都是普通只读 Node。输入的 Zod Schema 同时用于工具目录和实际节点输入。输出在保存本层 completed CP 前校验原始字节上限，父 ToolLoop 再核验完整工具反馈。用户可纠正的范围错误成为工具错误反馈；来源不一致、预算不足和持久故障不会映射成可继续的业务反馈。

恢复采用本层已保存的只读结果；宿主根资格校验仍需确认原输入、内容前缀、交换归档、交互原请求和完整反馈。工具目录摘要包括历史算法策略、原始输出上限与材料容量配置，改变这些配置不能悄悄沿用旧恢复依据。资源通过回答节点的一次 capture 取得同一个固定问题边界，未引入独立的“当前问题”状态。

`modelWaitMs` 是本地交互等候期限。它不修改 Provider 的独立总超时，也不取消外部发送。工具模式当前发布实际阶段状态及最终正式回答，不将可能以工具调用结束的模型中间正文当作回答预览。
